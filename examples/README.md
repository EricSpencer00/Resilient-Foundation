# Illustrative examples

The nonnegative example is a complete artifact-shape walkthrough for a proposed exact scalar task. It records Unknown formal/translation outcomes and NotRun runtime status.

The strict policy must reject it until actual required evidence is supplied and checked. That is an intentional fixture, not a failed completed implementation.

Bad manifests isolate policy mistakes: wrong hashes, fake proof status, missing dependencies, missing target relation, mixed profiles and unsupported capability claims. They are rejected by the specification validator without invoking an actual proof kernel.
